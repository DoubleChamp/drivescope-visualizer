# DriveScope 프로젝트 개요

## 문서 역할

이 문서는 DriveScope가 해결할 문제와 첫 번째 데모, MVP 범위를 정의하는 기준 문서다. 단계별 구현 순서와 현재 진행 상황은 각각 [ROADMAP.md](./ROADMAP.md)와 [PROGRESS.md](./PROGRESS.md)에서 관리한다.

## 제품 목적

DriveScope는 카메라, LiDAR, 객체 인식 결과, 예상 주행 경로를 하나의 타임라인에서 동기화해 자율주행 문제 장면을 분석하는 웹 기반 시각화 도구다.

목표는 특정 사고 위험 장면에서 센서 인식, 객체 인식, Planning 반응, 차량 제어 사이의 시간 관계를 빠르게 파악하는 것이다. Rerun 전체를 복제하거나 새로운 렌더링 엔진을 만드는 것은 목표가 아니다.

현재는 Next.js App Router·TypeScript·Three.js로 가상 급제동 분석 데모와 실제 nuScenes mini 센서 Viewer를 구현했다. 가상 모드는 보행자 등장·인식·예상 충돌·급제동과 객체 선택을 다루고, 실제 모드는 전방 JPEG·LiDAR·ego 위치와 방향을 같은 재생 시각에서 탐색한다. sweeps 비교 후 로컬 Viewer에 중간 원본 관측을 개별 Frame으로 연결하고 실제 모드의 갱신을 50ms로 맞췄다. 공개 데이터는 별도 교체 전까지 keyframe이며 실제 객체 인식·Planning·급제동 이벤트는 아직 연결하지 않았다.

timestamp 기반 Frame 선택, 최대 5개 CPU 캐시와 양옆 prefetch, Three.js Buffer 재사용, 디코딩 완료 후 이미지 교체와 오류 재시도를 검증했다. 성능 기준선·설치와 데모 재현·아키텍처를 정리하고 공개 Viewer의 실제 Blob 데이터 연결·재생·복구·모바일 표시를 확인했다. 실제/가상 데모 선택과 전환 시 초기화를 추가하고 로컬 production·공개 Viewer 양쪽의 브라우저에서 검증했다. [1분 촬영 대본](./DEMO_SCRIPT.md)을 따라 [60초 자막 영상](../public/demo/drivescope-demo.mp4)을 만들고 전체 디코딩·브라우저 재생·탐색을 검증했다. 현재 코드의 책임과 흐름은 [ARCHITECTURE.md](./ARCHITECTURE.md)를 따른다.

## 포트폴리오 소개

홈(`/`)은 이전의 간단한 카드 구조로 제공하며 **뷰어 열기 / 프로젝트 개요** 버튼으로 진입 화면을 나눈다. 포트폴리오 소개는 별도 `/project`에서 제공한다. 사용자가 선택한 **데이터 처리·성능 측정**을 중심으로 전처리·데이터 계약·CPU 캐시·GPU Buffer·이미지 교체의 결정과 근거를 설명하고, 조건이 명시된 기준선·측정 문서·1분 자막 영상·Viewer 열기 링크를 연결한다. `/viewer`는 센서 로그 탐색 화면으로 유지한다. 설명은 쉬운 문장과 단계별 흐름, 문제·해결 방법·확인한 결과로 제공하며 코드 펼치기와 파일별 코드 링크는 제거했다. 소개 페이지는 실제 센서 파일과 Three.js를 초기 로드하지 않으며 조작 가능한 작은 Frame 선택 예시만 Client Component로 만든다. 기존 영상과 측정 결과를 사용하며 새로운 향상률을 주장하지 않는다.

## 핵심 분석 질문

- 카메라는 보행자를 언제 확인했는가?
- LiDAR는 보행자를 언제 감지했는가?
- 객체 인식 결과는 언제 생성됐는가?
- 예상 주행 경로는 언제 보행자와 충돌했는가?
- Planning은 언제 반응했는가?
- 급제동은 적절한 시점에 발생했는가?

## 첫 번째 데모 시나리오

| 시간 | 장면 |
| --- | --- |
| 0~10초 | 차량이 정상 주행한다. |
| 10초 | 보행자가 도로에 등장한다. |
| 11초 | 카메라와 LiDAR 인식 결과에 보행자가 표시된다. |
| 12초 | 예상 주행 경로가 보행자 위치와 충돌한다. |
| 12.4초 | 급제동 이벤트가 발생한다. |
| 이후 | 차량 속도가 감소하고 예상 주행 경로가 변한다. |

이 시나리오는 가상 데이터로 분석 흐름을 검증한다. 실제 nuScenes mini 센서 모드는 별도로 제공하며 가상 인식·Planning·급제동 결과를 실제 장면에 섞지 않는다.

## MVP 범위

MVP에 포함한다.

- 전방 카메라 패널 1개
- LiDAR 포인트클라우드
- 차량과 보행자 3D 바운딩 박스
- 예상 주행 경로와 충돌 예상 구간 강조
- 재생, 정지, 타임라인 드래그
- 실제 센서 로그와 가상 급제동 데모 선택
- 센서별 타임스탬프 기반 프레임 동기화
- 급제동 이벤트 마커
- 객체 선택과 기본 정보 표시
- FPS, 포인트 수, 프레임 로딩 시간 표시
- 프레임 캐시와 이전·다음 프레임 미리 로딩

## MVP 제외 범위

사용자가 별도로 요청하기 전까지 다음 기능은 구현하지 않는다.

- 카메라 6개와 전체 레이더 데이터
- 복잡한 지도
- 사실적인 자동차 모델과 Blender 모델링
- 고급 조명과 사실적인 재질
- React Three Fiber
- 순수 WebGPU
- Rust 또는 wgpu 렌더러
- Rerun 전체 기능 복제
- 백엔드 서버
- 로그인과 사용자 권한
- 지나친 디자인 작업

## 성공 기준

MVP는 다음 조건을 만족할 때 성공으로 본다.

- 한 타임라인에서 카메라, LiDAR, 객체 인식, 예상 경로, 차량 상태, 이벤트를 함께 탐색할 수 있다.
- 첫 번째 데모의 보행자 등장부터 급제동 이후까지 시간 관계를 재생과 탐색으로 확인할 수 있다.
- 객체를 선택해 기본 정보를 확인하고, 예상 충돌 구간과 급제동 시점을 식별할 수 있다.
- 필요한 프레임만 로딩하고 주변 프레임을 캐시하며, 포인트 Buffer를 재사용한다.
- FPS, 포인트 수, 프레임 로딩 시간을 화면에서 확인해 성능 변화를 수치로 비교할 수 있다.
- React의 UI·입력·재생 상태와 Three.js의 장면·GPU 리소스·렌더 루프 책임이 분리되어 있다.
- 구현 단계마다 사용자가 핵심 원리와 코드의 역할을 설명할 수 있다.
